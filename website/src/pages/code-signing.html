Code signing policy

This is a draft, prepared for a possible application to a code signing programme. SnapForge is not code-signed today. Nothing on this page means that any SnapForge file is signed.

Status: draft, awaiting the owner's decision. The project has not applied for, or received, a code signing certificate. This page is not linked from the site's navigation. It will be completed and linked only after a signing service has accepted the project, and the attribution below will only be shown once it is true.

What would be signed

  • Only release files built by the project's GitHub Actions workflow on GitHub-hosted runners, from a tagged commit of the public repository bazeocrisy/SnapForge: SnapForge.exe, and the installer SnapForge-<version>-win-x64-setup.exe (which contains the signed SnapForge.exe).
  • No file built on a personal computer, no third-party program and no file that did not come from that workflow would be signed.
  • Every signing request would be approved manually by an approver (below) after checking that it comes from the expected workflow run and commit.

All team members use multi-factor authentication for GitHub and for the signing service.

Privacy

The SnapForge app contains no network code: it does not transfer any information to other networked systems, and has no telemetry, accounts, update checks or uploads. See the privacy page.

Attribution

If the project is accepted by the SignPath Foundation programme, this section will state: “Free code signing provided by SignPath.io, certificate by SignPath Foundation.” That is not the case today.

Windows warnings

Code signing identifies the publisher of a file; it does not guarantee that Windows SmartScreen never warns. SmartScreen also relies on reputation that builds up over time.
